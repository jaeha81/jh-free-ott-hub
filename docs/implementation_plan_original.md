# 무료 영화·애니 검색형 OTT 허브 — 원본 구현계획서

> 이 문서는 재하님이 작성한 원본 구현계획서(docx)를 마크다운으로 변환한 것입니다.
> 정책, 로드맵, 리스크 관리의 원천 문서로 참조하세요.

---

**문서 목적:** 불법 우회·무단 재송출 없이, 전 세계 무료·합법 소스를 한곳에서 검색하고 접속할 수 있는 OTT형 허브의 구현계획 정리

**권장 서비스 형태:** 초기에는 '검색·연결 허브 + 일부 공공도메인 직접 재생' 구조를 권장

**핵심 사용자 경험:** 모바일·태블릿·TV에서 동일한 콘텐츠 탐색 경험 제공 / 리모컨(D-pad)·터치 동시 대응 / 저지연·고화질 최적화

**기준일:** 2026년 3월 28일

---

## 최종 권장안 요약

1. 넷플릭스형 '재송출 OTT'를 바로 만드는 방향은 법적·기술적 리스크가 크므로 초기안에서 제외한다.
2. 1차 MVP는 무료·합법 플랫폼의 메타데이터를 모아 검색하고, 사용자를 공식 재생 경로로 연결하는 허브로 만든다.
3. 공공도메인·권리 명확 콘텐츠만 앱 내 직접 재생하고, 외부 플랫폼 콘텐츠는 딥링크/공식 웹 열기 방식으로 처리한다.
4. UI는 OTT처럼 만들되, 백엔드는 '검색 허브'로 설계한다. 이 구조가 가장 안전하고 확장 가능하다.

## 1. 프로젝트 목표와 설계 원칙

이 서비스의 본질은 '전 세계 무료 영화·애니메이션을 한곳에서 쉽게 찾게 해주는 안전한 허브'입니다.

### 1-1. 반드시 지켜야 할 핵심 원칙

- VPN 우회, 국가 제한 회피, 무단 미러링, 보호된 스트림 재송출은 구현 범위에서 제외한다.
- 무료 여부만 보지 말고, 권리 구조가 명확한지 여부를 기준으로 소스를 분류한다.
- 공식 앱/웹으로 연결 가능한 콘텐츠와 앱 내부에서 직접 재생 가능한 콘텐츠를 명확히 분리한다.
- 재생 기능보다 먼저 '검색 정확도·디바이스 호환성·리모컨 조작성·성능'을 품질 기준으로 둔다.
- 자막/번역 기능은 저작권과 기술 제약을 고려해 '합법 소스 우선 + 자체 생성은 허용 범위 내에서만' 적용한다.

### 1-2. 서비스 형태 비교

| 안 | 개발 난이도 | 법적 리스크 | 사용자 편의 | 유지비 | 판단 |
|----|-----------|-----------|-----------|--------|------|
| A. 각 사이트 직접 방문 | 낮음 | 낮음 | 낮음 | 낮음 | 안전하지만 UX가 약함 |
| B. 검색·연결 허브 | 중간 | 낮음~중간 | 높음 | 중간 | **초기 권장안** |
| C. 자체 통합 스트리밍 OTT | 매우 높음 | 높음 | 매우 높음 | 높음 | 장기 검토만 가능 |

## 2. 권장 서비스 구조

- **직접 재생 층:** 공공도메인, 권리 명확 오픈 아카이브, 자체 보유 라이선스 콘텐츠
- **연결 층:** Plex, Viki, Kanopy 등 공식 서비스의 상세 페이지 또는 공식 앱으로 이동
- **관리 층:** 메타데이터 수집, 국가/언어/장르 분류, 링크 검증, 품질 점검, 사용자 히스토리 저장

### 2-1. 콘텐츠 소스 분류 정책

| 구분 | 예시 | 앱 내 직접재생 | 외부 연결 | 운영 원칙 |
|------|------|-------------|---------|----------|
| 공공도메인/오픈아카이브 | Internet Archive 등 | 가능 | 가능 | 소스 원문 권리 상태를 개별 확인한 뒤 인앱 재생 |
| 도서관·기관 연동형 | Kanopy | 비권장 | 권장 | 회원/도서관 로그인 구조 존중, 메타데이터만 수집 |
| 광고형 무료 플랫폼 | Plex, Viki | 비권장 | 권장 | 공식 앱 또는 웹 상세로 넘기는 구조 |
| 공영/공공기관 콘텐츠 | 국가별 공공기관·영상 아카이브 | 조건부 | 가능 | 라이선스 문구가 명확한 작품만 포함 |

### 2-2. 절대 제외 항목

- 국가 제한을 우회하기 위한 VPN 내장 기능
- 권리자 허락 없이 외부 OTT 영상을 앱 안에서 프록시/미러링 재생
- 브라우저 자동 제어로 보호된 유료 서비스 재생 우회
- 자막 보호가 걸린 스트림을 무단 추출하여 자체 저장하는 기능

## 3. OTT형 화면 설계

### 3-1. 추천 화면 정보구조

- **홈:** 오늘의 추천 / 국가별 무료 영화 / 무료 애니메이션 / 신규 발견 / 고전 명작 / 가족용
- **탐색:** 국가, 언어, 장르, 자막 가능 언어, 직접재생 가능 여부, 외부 앱 필요 여부 필터
- **상세:** 포스터, 시놉시스, 연도, 국가, 원 출처, 자막 가능 여부, 재생 방식(인앱/외부연결), 화질 정보
- **플레이어:** 인앱 재생일 때만 표시. 자막 선택, 속도 조절, 품질 선택, 이어보기
- **설정:** 언어, 자막 기본값, 연결 가능한 외부 앱, TV 조작 모드, 네트워크 품질 옵션

### 3-2. 리모컨 + 터치 동시 대응

| 입력 방식 | 핵심 요구 | 구현 포인트 | 주의사항 |
|----------|---------|-----------|---------|
| 터치 | 탭, 스와이프, 빠른 탐색 | 카드 크기 크게 / 터치 타깃 44dp 이상 | 과밀 배치 금지 |
| 리모컨(D-pad) | 상/하/좌/우/확인/뒤로만으로 조작 | 포커스 이동 명확화 / 행 단위 탐색 | 포커스가 사라지면 UX 붕괴 |
| 마우스 | 포스터 Hover·클릭 | 데스크톱용 세부 정보 표시 | TV UX와 충돌 주의 |
| 모바일→TV 연결 | 핸드폰은 리모컨, TV는 출력화면 | 두 화면 역할 분리 가능 | 동기화 지연 체크 필요 |

## 4. 시스템 아키텍처

### 4-1. 권장 스택

- **프론트엔드:** Next.js 기반 반응형 웹앱(PWA) 우선
- **백엔드:** FastAPI
- **DB:** PostgreSQL 또는 SQLite 기반 메타데이터 저장
- **검색:** MVP는 DB 필터 + 전문검색으로 시작
- **자동화:** Make.com은 운영 알림에만 사용. 재생 경로에는 넣지 않음

### 4-2. 구조 흐름

1. 소스 수집기 (API/RSS/허용된 HTML 파서)
2. 메타데이터 정규화
3. 링크 검증 및 지역/언어 태깅
4. 콘텐츠 인덱스 저장
5. 사용자 검색/필터 응답
6. 직접재생 또는 외부 공식 경로 연결

## 5. 콘텐츠 수집 및 정규화 설계

### 5-1. 최소 데이터 스키마

| 필드 | 예시 | 설명 |
|------|------|------|
| title | Roman Holiday | 표준 제목 |
| original_title | 로마의 휴일 | 원제 또는 현지화 제목 |
| country | US / JP / KR / CN | 제작국가 또는 소스국가 |
| source_name | Plex / Viki / Kanopy / IA | 원 출처 |
| watch_mode | in_app / external | 직접재생 가능 여부 |
| availability_note | 도서관 로그인 필요 | 재생 조건 요약 |
| subtitle_languages | ko,en,ja | 자막 가능 언어 |
| poster_url | ... | 포스터 이미지 |
| quality_hint | HD / SD / Unknown | 공개된 화질 정보 |

### 5-2. 운영용 태그 체계

- **genre:** 드라마, 액션, 애니메이션, 가족, 고전, 다큐, 스릴러 등
- **audience:** 어린이, 가족, 일반, 청소년 이상
- **license_class:** public_domain / institutional / ad_supported / unknown
- **region_hint:** global / asia / korea / japan / china / region_limited
- **subtitle_state:** official_subtitles / no_subtitles / user_generated_prohibited

### 5-3. 수집 방식 우선순위

1. 공식 API 또는 공식 검색 페이지가 있는 소스
2. robots 정책을 존중하는 범위의 메타데이터 수집
3. 사람이 검수해서 수동 등록하는 큐레이션 목록
- **배제:** 영상 스트림 주소 추출, DRM 우회, 계정 인증이 필요한 실제 재생 URL 탈취

## 6. 재생, 자막, 화질 전략

### 6-1. 재생 정책

- 공공도메인/자체 권리 확보 콘텐츠: 앱 내 플레이어로 직접 재생
- 외부 무료 플랫폼 콘텐츠: 공식 앱 열기 또는 공식 웹 상세 열기

### 6-2. 자막 전략

| 상황 | 권장 방식 | 난이도 | 비고 |
|------|---------|--------|------|
| 공식 자막 제공 | 그대로 사용 | 낮음 | 가장 안전 |
| 공공도메인 영상 | WebVTT/SRT 자체 관리 | 중간 | 직접 운영 가능 |
| 실시간 번역 자막 | 허용 콘텐츠에서만 별도 엔진 | 높음 | 저작권/지연 관리 |
| 외부 보호 스트림 | 자체 오버레이 자막 비권장 | 높음 | 권리/기술 이슈 |

### 6-3. 고화질·저지연 전략

- 썸네일, 포스터, 상세 정보는 지연 로딩(Lazy load)과 프리페치로 분리
- 직접 재생 콘텐츠는 HLS 기반 적응형 비트레이트 구조를 기본값
- 목표 KPI: 첫 화면 2초 이내 로드, 포커스 이동 즉시 반응, 카드 스크롤 60fps

## 7. 디바이스 연결 및 TV 사용 시나리오

### 7-1. 권장 시나리오 우선순위

1. TV 브라우저 또는 TV 앱에서 직접 허브 사용
2. 휴대폰 앱/PWA를 리모컨 겸 탐색기로 쓰고, TV는 화면 출력
3. HDMI 또는 무선 미러링으로 휴대폰 화면을 TV에 출력
4. Android TV 전용 앱으로 확장하여 D-pad UX 최적화

## 8. 개발 단계 로드맵

| 단계 | 핵심 산출물 | 왜 필요한가 |
|------|-----------|-----------|
| 0단계. 정책 확정 | 소스 포함/제외 기준 문서화 | 불법 리스크 차단 |
| 1단계. 데이터 MVP | 필드 확정, 50~200개 시드 데이터 | 검색 허브 뼈대 확보 |
| 2단계. UX MVP | OTT형 홈/탐색/상세, 반응형, 포커스 처리 | 사용성 검증 |
| 3단계. 재생 연결 | 인앱 재생 + 외부 연결 + 이어보기 | 핵심 동작 완성 |
| 4단계. 운영도구 | 관리자 패널, 링크 상태검사, 큐레이션 | 운영 가능화 |
| 5단계. 고도화 | 추천, 다국어, 즐겨찾기, TV 앱, 자막 실험 | 확장 |

### 8-1. 1차 MVP 완료 기준

- 무료·합법 소스 3~5개 이상 연결
- 최소 100개 이상 작품 메타데이터 검색 가능
- 국가/장르/자막 필터 작동
- 공공도메인 작품 1개 이상 인앱 재생 성공
- 외부 플랫폼 작품 1개 이상 공식 링크/앱 연결 성공
- 모바일/데스크톱/TV 브라우저에서 기본 조작 가능

## 10. 실행 지시

- 장르를 영화 + 애니메이션으로 고정
- 소스 1차 3종: 공공도메인 아카이브 1개, 광고형 무료 플랫폼 1개, 아시아 무료 플랫폼 1개
- UI는 홈/탐색/상세/설정 4화면만
- 재생은 '인앱 1종 + 외부연결 2종'만 성공시키고 확장
- TV 리모컨 대응은 처음부터, 실시간 번역 자막은 후순위

## 부록 A. 참고 공식/기술 출처

- Plex 공식: 무료 스트리밍 및 글로벌 접근성 안내
- Rakuten Viki 공식: 무료/광고형 시청 및 앱 지원 안내
- Kanopy 공식: 공공도서관 또는 대학 계정 기반 무료 스트리밍 구조
- Internet Archive 공식: Feature Films / Moving Image Archive 공개 아카이브
- Android Developers 공식: TV 디자인, D-pad 내비게이션, TV 앱 품질 가이드
- Apple 공식 HLS 문서: 적응형 스트리밍 동작
- MDN 공식: HTML video track, WebVTT 기반 자막/캡션 처리

## 부록 B. 개발 착수 전 사전 확인

- 소스별 이용약관 검토 문서 1회 정리
- 직접재생 대상과 외부연결 대상을 별도 표로 분리
- 국가/언어/장르 태그 정책 확정
- TV용 리모컨 QA 기기 1대 확보
- PWA 우선인지 Android TV 우선인지 1차 목표 명확화
